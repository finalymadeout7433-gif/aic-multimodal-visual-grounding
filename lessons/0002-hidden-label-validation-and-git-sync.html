第二课：没有正式 bbox，模型怎样训练和验证？

目标：你能分清训练集、验证集、正式测试集和排行榜，也能说清 Git 的四个位置。

一、正式初赛数据不是训练集

数据有没有 bbox正确用途
合法的外部/自建训练集有计算 loss，更新模型权重
独立验证集有比较模型、选参数，不更新权重
官方单样例仅 1 条有 bbox检查读取、坐标和评测代码
正式 9,555 条 Query没有只做推理，生成提交 JSON/ZIP

正式集的真实 bbox 藏在比赛平台中。规则明确禁止把正式测试集用于训练，也不能人工补 bbox。

二、我们的完整验证阶梯

自动化单元测试官方单样例外部有标签验证集 正式集无标签试跑平台隐藏标签评分
  1. 单元测试：验证 bbox 互转、IoU、JSON 和 ZIP，没有模型分数含义。
  2. 官方单样例：只能称为 sanity check，不能用 1 条数据判断模型强弱。
  3. 外部有标签验证集：用 ACC@0.5 比较 Florence、GroundingDINO 和后续融合方案。
  4. 正式集 dry run：统计无输出率、非法框率、耗时和显存，不计算本地 ACC。
  5. 排行榜：上传预测 ZIP，由平台隐藏 bbox 给出目标域分数。

每次排行榜提交都要绑定实验编号、Git commit、配置文件和说明。不要每改一行就上传，也不要反复根据公榜“猜答案”。

三、正式数据怎样参与项目？

训练阶段：
外部有标签图像 + Query + bbox
        ↓
训练代码更新权重
        ↓
独立验证集选择最佳权重

比赛阶段：
最佳固定权重 + 正式图像 + Query
        ↓
推理代码预测 bbox
        ↓
submission.json → ZIP → 比赛平台评分

正式数据会参与最终推理，但不会参与反向传播训练。如果以后要训练，应先准备合规的有标签数据，并检查许可证、数据来源以及是否与测试集重叠。

四、初赛上传的不是模型

依据当前官方材料，初赛、复赛上传的是测试集预测结果 ZIP；JSON 只添加或修改 bbox。到半决赛才要求同时提交代码、预测结果、模型文件、环境说明和技术报告。

五、Git 的四个位置

位置你在哪里看到它保存什么
工作区 Working TreeVS Code 资源管理器和“更改”刚编辑、尚未选入版本的文件
暂存区 Staging Area源代码管理里的“暂存的更改”准备放进下一次 commit 的快照
本地仓库 Local Repository.git 和 git log已经 commit 的历史版本
远程仓库 GitHubGitHub 网页执行 push 后的在线副本
修改/运行 ≠ 自动上传

编辑 → git add → git commit → git push
工作区   暂存区      本地仓库      GitHub

运行程序只会产生结果文件。除非专门配置自动化，否则 Git 不会自动暂存、提交或上传。VS Code 的“同步更改”也不会替你决定提交哪些未提交文件。

六、每一版建议操作

git status
pytest
git add 要保存的文件
git commit -m "feat: 描述这一版改变"
git tag v0.2.0
git push origin main
git push origin v0.2.0

数据集、模型权重和 outputs/ 不进入 Git；仓库保存代码、配置、测试、报告和复现命令。

七、你的练习

  1. 在 VS Code 左侧打开“源代码管理”，找到“更改”。
  2. 运行 git status，观察本课文件此时属于哪个位置。
  3. 用一句话回答：为什么正式 9,555 条数据能推理，却不能训练？
  4. 用自己的话复述：修改文件后，为什么 GitHub 不会自动变化？
